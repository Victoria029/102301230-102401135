# 目录说明与使用说明

> 根目录 `README.md` 是速览版（怎么跑、验收路线、功能清单、已知限制）。
> 本文补充更细的结构说明、命名约定、开发约定与数据说明。

---

## 一、目录是怎么组织的

按「页面 → 样式 → 逻辑 → 测试 → 文档」五层分开。核心思路是**页面文件只管结构，业务规则全部收在数据层**。

```
campus-lost-found/
│
├─ ① 页面层：9 个 HTML，文件名即用途
│    index.html        首页
│    search.html       搜索页
│    publish.html      发布 / 编辑页
│    success.html      发布成功页
│    detail.html       信息详情页
│    verify.html       认领验证答题页
│    verify-result.html 验证结果页
│    appeal.html       申诉页
│    mine.html         我的（个人中心）
│
├─ ② 样式层：3 个 CSS
│    css/tokens.css      设计令牌（色板、圆角、阴影、字号、间距）
│    css/components.css  通用组件（卡片、标签、按钮、表单、题目编辑器、弹层、空状态）
│    css/layout.css      响应式布局（900px 断点）
│
├─ ③ 逻辑层
│    js/config.js        业务字典（类型、分类与搜索引导、地点、出题模板、验证规则）
│    js/utils.js         纯函数工具（时间、文本归一化、图片压缩、剪贴板）
│    js/store.js     ★   数据层：全部业务规则（含申诉通道与老数据迁移）
│    js/seed.js          演示数据（招领信息自带 3~4 道客观题）
│    js/ui.js            界面公共层（导航外壳、卡片渲染、轻提示、弹窗、一键复制）
│    js/page-*.js        9 个页面的控制器，与 HTML 一一对应
│
├─ ④ 测试层
│    test/test.html      测试入口，双击即跑
│    test/specs/main.spec.js 用例（10 组，共 53 个用例）
│    test/lib/           Mocha 与 Chai 浏览器构建（随仓库提交，离线可用）
│
└─ ⑤ 文档层
     docs/设计文档.md           解题思路、架构、数据模型、关键实现与取舍
     docs/目录说明与使用说明.md  本文
     docs/PSP表格.md            PSP 记录与偏差分析
     docs/流程图.md             四张 Mermaid 图
     README.md                 速览版说明
```

### 层与层之间的依赖是单向的

```
HTML  →  page-*.js  →  ui.js  →  store.js  →  config.js / utils.js
                                     ↓
                              存储适配器（localStorage / sessionStorage / 内存）
```

`store.js`、`config.js`、`utils.js` **不引用任何 DOM 对象**，所以它们能被单元测试直接 `require`，也能在浏览器里当普通脚本加载。这是"测试不需要 jsdom、不需要起服务器"的前提。

## 二、命名约定

| 对象 | 约定 | 例子 |
| --- | --- | --- |
| 页面 | 小写、多词用连字符 | `verify-result.html` |
| 脚本 | `page-xxx.js` 一定是某个 HTML 的控制器，与页面同名，一眼能对上 | `page-verify-result.js` |
| 模块 | 不带 `page-` 前缀的是被复用的公共模块 | `store.js`、`ui.js`、`config.js` |
| 数据字段 | 一律小驼峰，语义直白 | `happenedAt`、`contactWay`、`doneType` |
| 字典类字段 | 存 `key` 而不是中文，中文只出现在 `config.js` | `category: 'rain'`、`type: 'found'` |
| CSS 类 | 语义化前缀，避免"两种用途共用一个类名" | `.home-search-entry` 与 `.search-input` 是**两个**类 |
| 测试用例名 | 写"应该发生什么"，不写"测哪个函数" | 「未答完提交不消耗次数」而不是「test submitClaim」 |

### 一条踩过的坑，写进约定里

**不要给两种不同用途的元素起同一个类名。**

开发过程中，首页那个"长得像搜索框"的入口链接和搜索页真正的输入框本来都叫 `.searchbox`，结果桌面端一条 `.searchbox { display: none }` 把**真正的输入框**一起藏掉了——页面没报错、单元测试也全绿，用户却一个字都打不进去。

所以现在入口叫 `.home-search-entry`，真输入框叫 `.search-input`，各管各的。后续排查同类问题时，可用"元素尺寸是否为 0 / 该位置上最顶层的是谁"来验证（`getBoundingClientRect()` + `document.elementFromPoint()`）——因为**"页面没报错"和"用户能用"是两回事**。

## 三、怎么运行

### 运行网页

1. 把整个 `campus-lost-found` 文件夹下载到本地（`git clone` 或 GitHub 页面 `Code → Download ZIP` 后解压）；
2. 保持目录结构不变；
3. **用谷歌浏览器 Chrome 双击打开根目录下的 `index.html`**。

不需要安装任何东西，不需要起服务器，不需要联网。第一次打开会自动灌入一批演示数据。

> **务必用 Chrome。** 本项目用 `localStorage` 存数据。Chrome 在 `file://` 协议下把所有本地文件视为同一来源，页面之间能共享数据；Firefox 会把每个文件当成独立来源，导致「发布成功后跳到成功页，数据却读不到」。本次作业统一指定 Chrome。

### 运行单元测试

双击 **`test/test.html`**，Chrome 打开后自动跑完全部用例并给出报告。

跑完后 `<html>` 上会写入自检标记，方便命令行检查：

```
<html data-selftest="PASS|passing=53|failing=0">
```

## 四、数据说明

### 存在哪里

| 项 | 值 |
| --- | --- |
| 存储键 | `lf_db_v1`（单键，整个库一个 JSON） |
| 位置 | 浏览器的 localStorage |
| 旧版兼容键 | `lost_found_list`（第一次结对作业那份脚手架用的键，首次打开时会被一次性迁移过来） |

### 单键存整个库的理由

写一次就是一个原子操作；迁移、导出、清空都只需要处理一个对象。代价是每次写都会重写整个库——在本项目的量级（几十条信息、照片压缩到 40KB 左右）完全可以接受。

### 数据会丢吗

| 情况 | 结果 |
| --- | --- |
| 关掉浏览器再打开 | 还在（localStorage） |
| 清除浏览器数据 / 换浏览器 / 换设备 | **看不到**（没有后端，这是必然的） |
| 浏览器不允许 localStorage | 降级到 sessionStorage：同一标签页内流程能走完，关掉标签页会丢 |
| 两种 storage 都不允许 | 降级到内存：刷新即丢 |

降级发生时，页面顶部会出现一条提示条，明确告诉用户当前数据的保留范围——不让他在毫不知情的情况下丢数据。

**想备份 / 迁移**：「我的 → 本地数据 → 导出为 JSON」，在另一台设备上用「导入 JSON」恢复。

### 演示数据长什么样

首次打开灌入 11 条信息，其中 **3 条归属于使用者本人**（本机 `ownerId`），所以点进「我的发布」不是一片空白，可以立刻演示"标记已归还""处理申诉"这类需要发布者身份才用得上的功能。

演示数据刻意覆盖了认领验证的三种状态：

| 演示数据 | 用来演示什么 |
| --- | --- |
| 白色 AirPods Pro（本机发布，已答满 3 次，带一条待处理申诉） | 「我的 → 人工审核」的完整处理流程 |
| 校园卡一张（带 4 道题，可作答） | 认领验证主流程：答错 → 答对 → 解锁 |
| 藏蓝色三折雨伞（已答满 3 次） | 从认领人视角看到「提交申诉」入口 |
| 《高等数学》上册（「其他」类） | 信任模式：不出题、联系方式直接公开 |

**想知道某道题的正确答案**：在「我的」里点那条信息的「编辑」，题目编辑器里被圆点选中的那一项就是答案。

**想恢复初始状态**：「我的 → 本地数据 → 恢复演示数据」。

## 五、开发约定

### 加一个新分类

只改 `js/config.js` 里的 `LF.CATEGORIES` 一处：

```js
{
  key: 'sports', name: '运动器材', icon: '🏸',
  allowVerify: true,                    // 要不要出认领验证题
  searchHint: '本类按……搜索。……不公开。',  // 给失主看的搜法引导
  templates: [ /* 出题模板 */ ]
}
```

首页分类条、发布页分类选择、搜索引导、出题模板下拉框、`facets()` 统计会一起生效——因为它们都只读这一份数据，页面里没有第二份分类名单。测试里有一条用例专门断言"每个分类都要有引导语""允许出题的分类都要有模板"。

### 加一个新的校验规则

加在 `js/store.js` 的 `validatePost()` 里，返回 `errors.字段名 = '中文提示'`。发布页会自动把错误定位到对应的 `#f-字段名` 与 `#err-字段名` 上（命名就是这么来的）。

### 改数据结构

1. `LF.DATA_VERSION` +1；
2. 在 `migrate()` / `normalizeStoredPost()` 里补一条迁移分支；
3. 补一条用例：造一条老版本的数据，断言迁移后能正常工作。

**别只补字段就完事**——还要问一句"有没有已经不该生效的数据需要清理"。本项目就踩过这个：规则改成「其他」类不出题之后，历史数据里残留的题目必须一并清掉，否则发布者会被锁在一个"详情页还在要求答题、发布页却已经没有出题入口"的旧流程里，他连"把这套题删掉"都做不到。

### 跑测试

双击 `test/test.html` 即可。改完 `store.js` / `config.js` / `utils.js` / `seed.js` 之后都应该跑一遍。

新增用例：在 `test/specs/` 下新建 `<模块>.spec.js`，并在 `test/test.html` 的用例列表里加一行 `<script>`。**别忘了这一步**——加了文件但没加引用，用例不会跑，而页面看起来一切正常。
